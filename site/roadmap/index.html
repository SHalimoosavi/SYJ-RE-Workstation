Roadmap and delivery status

Implemented capabilities and planned work are separate. No release-date promise is implied.

Phase 0 — Foundation

Bash analyzer, SHA-256, AAPT metadata/permissions/manifest, ZIP inventory, optional signature/JADX hooks, local reports and report comparison.

Implemented; regression-checked.

Phase 1 — Verified static foundation

Four-release CI matrix, regression tests, installation documentation, contributor workflow and reproducible example report.

Passed on Debian 12/13 and Ubuntu 22.04/24.04 GitHub-hosted amd64 containers.

Main-branch compatibility matrix run #94 passed on commit f9f58af. CI covers GitHub-hosted Debian/Ubuntu amd64 containers only, not physical Android devices, Termux itself or Debian PRoot on Android.

Phase 2 — Static analysis expansion

APKTool integration, ELF/native inspection, dedicated DEX analysis and richer report formats.

Planned; not shipped.

Phase 3 — Runtime analysis

Separate, controlled dynamic instrumentation and runtime-analysis effort.

Planned; not shipped and outside current static analyzer.

Validation boundaries

CI does not validate physical Android devices, Termux itself, Debian PRoot on Android or other CPU architectures. Debian bootstrap installs YARA and binutils, but analyzer does not run YARA or inspect ELF/native binaries. APKTool is installed in CI for package checks but is not invoked by the analyzer.

See the repository roadmap and CI validation scope.
